מטרות השיעור

  • התלמידים יבנו משחק ארקייד שעובד, עם לולאת משחק מלאה: תנועה, יצירת אויבים או פריטים, התנגשות, ניקוד וחיים או טיימר, ומסך סיום.
  • התלמידים יסבירו שלושה מושגי יסוד בתכנות משחקים: ספרייט, אירוע ("כאשר... אז...") והתנגשות.
  • התלמידים יעצבו 2 ספרייטים מקוריים בפלטה אחידה, ויעבירו אותם מ-Piskel לעורך הפיקסלים של MakeCode.
  • התלמידים יחוו מחזור בדיקה אמיתי: שחקן זר ← מדידת זמן הבנה ← רישום באגים ← תיקון ← בדיקה חוזרת במרתון.
  • התלמידים ישתמשו ב-Gemini כ"חבר לבאגים" (מה קורה / מה רצינו / מה ניסינו), ולא ככותב קוד, ויתעדו בשקיפות מה ה-AI עשה.
  • כל סטודיו יגיש קישור שיתוף למשחק וכרטיס מכונה של עד 15 מילים, ויפעיל את המכונה מול קהל אמיתי.

למה ערב ארקייד (ולא שיעור קוד רגיל)

משחק נבדק באמת רק כשמישהו אחר משחק בו. מרתון הפלייטסט נותן לכל סטודיו עשרות שחקנים אמיתיים ב-13 דקות. כרטיסי השחקן הופכים "אהבתי" למספר שאפשר לספור, וטבלת השיאים יוצרת תחרות כפולה: בין היוצרים (מי בנה מכונה שרוצים לחזור אליה) ובין השחקנים (מי שובר את השיא). כך גם תלמיד/ה שהתקשה בקוד מנצח/ת משהו בערב.

המבנה: סיפור מסגרת (אולם שנפתח מחדש) ← מיני-שיעור עם הדגמה חיה ← ספרינט בנייה ← בדיקת מכונה (נקודת ביקורת עם שחקן זר) ← ספרינט תיקונים והגשה ← האולם נפתח ← טקס.

הסוד של השיעור הוא "קטן שעובד". עד דקה 40 כל סטודיו חייב משחק שזז ויש בו התנגשות. כל השאר (אנימציות, שלבים, צלילים) מגיע רק אחרי שזה עובד. מקרה Celeste (שקף 14) נותן לזה שפה משותפת.

הכנה לפני השיעור (כ-40 דקות, פעם אחת)

  • לפתוח ממחשב של בית הספר: arcade.makecode.com ← New Project ← לוודא שהסימולטור משמאל עולה ושמקשי החצים מזיזים ספרייט.
  • לפתוח piskelapp.com ← Create Sprite. לוודא שאפשר להוריד קובץ (Export ← PNG ← Download).
  • לוודא ש-gemini.google.com, forms.google.com ו-sheets.google.com לא חסומים. אם משהו חסום: לתאם עם רכז/ת התקשוב.

2. מכונת הדגמה משלכם (15 דקות)

  • לבנות ב-MakeCode את "המכונה ב-4 בלוקים" (שקף 10, הצעדים המלאים בשליף): שחקן שזז, אויב כל 2 שניות, התנגשות שמורידה חיים, 3 חיים, טיימר 30 שניות וניצחון בסוף הטיימר.
  • Share ← לשמור את הקישור. אם ההדגמה החיה נתקעת, פותחים את הקישור. בנוסף, במצגת יש מכונה לדוגמה שמשחקים בה (שקף 11).
  • לשמור גם פרויקט ריק פתוח בלשונית, לבנייה חיה מול הכיתה.

3. טופס "הגשת מכונה" ב-Google Forms (10 דקות)

  2. שאלות (כולן "חובה" חוץ מ-5):

    2. שם המשחק: תשובה קצרה.
    3. קישור שיתוף מ-MakeCode Arcade: תשובה קצרה. אפשר להוסיף אימות תשובה: "טקסט ← מכיל ← makecode".
    4. כרטיס המכונה (עד 15 מילים): פסקה.
    5. קובץ PNG של הספרייטים: העלאת קובץ (מחייב שהמשיב/ה מחובר/ת לחשבון Google. מי שלא מחובר/ת מדלג/ת: הספרייטים נמצאים בתוך המשחק בכל מקרה).
    6. כמה באגים תיקנתם לפי דף הבאגים? תפריט נפתח 0 / 1 / 2 / 3.
    7. מה Gemini עשה: פסקה.
    8. מה אנחנו עשינו: פסקה.
    9. הערכה עצמית במחוון (1–4) לכל קריטריון: רשת שאלות אמריקאיות (שורות: מכניקה, פיקסלים, בדיקה, צוות · עמודות: 1–4).
  3. הגדרות ← תגובות ← לוודא ש"איסוף כתובות אימייל" כבוי (אלא אם רוצים לזהות מגישים).
  4. פרסום ← גישה כללית ← פרסום הטופס. ואז "שיתוף" ← העתקת הקישור של המשיב/ה ← סימון "קיצור כתובת URL".
  5. תשובות ← קישור אל Sheets. בשיעור מקרינים את לשונית התשובות כדי לראות מי עוד לא הגיש.
  6. להדביק את הקישור הקצר ב-Google Classroom או בקבוצת הכיתה, או להכין קוד QR.

4. גיליון "טבלת השיאים" ב-Google Sheets (5 דקות)

  1. sheets.google.com ← גיליון ריק ← שם: טבלת השיאים · ערב הארקייד.
  2. שורה 1: שחקן/ית · מכונה · שיא · אושר ע״י המפעיל/ה. תצוגה ← הקפאה ← שורה אחת.
  3. עמודה B: הוספה ← תפריט נפתח ← שמות 6 הסטודיו.
  4. עמודה C: עיצוב ← עיצוב מותנה ← סולם צבעים (הגבוה בירוק).
  5. גיליון שני "כרטיסים": סטודיו · כרטיסי שחקן · פיקסל זהב · באגים שתוקנו, עם =SUM בתחתית.
  6. שיתוף ← כל מי שיש לו את הקישור ← עורך (רק לשיעור הזה, ולסגור אחריו). אם לא רוצים שתלמידים יערכו: רק המדריך/ה ממלא/ת, והמפעילים מדווחים בקול או על דף השיאים המודפס.
  7. חלופה מובנית: במצגת יש טבלת שיאים, ספירת כרטיסים ולוח ניקוד חיים (שקפים 37–39), שנשמרים בדפדפן. אפשר להסתפק בהם.

5. חומרים וחדר

  • להדפיס לפי רשימת ההדפסה. כרטיסי שחקן על נייר צבעוני, ופיקסל זהב על נייר צהוב.
  • כוס או קופסה לכל מכונה (קופת כרטיסים), עם פתק שם הסטודיו.
  • רמקול למחשב המדריך/ה: המצגת מנגנת צלילי ארקייד (פתיחה, טיימר שנגמר, מוזיקה למרתון, תרועה).
  • לפתוח את המצגת ולבדוק מסך מלא (מקש F). ללחוץ "↺ איפוס לכיתה חדשה" בשקף 39, אם הכיתה הקודמת השאירה נתונים.
  • לסדר מראש את הצוותים (4–5 בסטודיו, מעורבים ברמות), ולרשום את השמות בלוח הניקוד (שקף 29, לוחצים על שם הסטודיו ומקלידים).

איך מריצים את השיעור כאירוע

  • סידור החדר: כל סטודיו בשולחן קבוע. "המכונה" (המחשב עם MakeCode) עומדת בקצה השולחן, עם המסך כלפי החוץ, כך שבמרתון אפשר לגשת אליה בלי להיכנס לשולחן.
  • אות עצירה: "פאוז!" + יד מורמת. כולם עוצרים, ידיים מהמקלדת. אפשר לנגן את צליל הפתיחה (כפתור INSERT COIN בשקף 1) כאות.
  • מי מדבר עם המדריך/ה: רק מנהל/ת הסטודיו, ורק אחרי שהסטודיו בדק במרפאת הבאגים (שקף 27) וב-Gemini.
  • רמזור AI: 🔴 לרעיון, לציור ולכרטיס היציאה · 🟡 לבאגים (Gemini שואל ומסביר) ולקיצור כרטיס המכונה. אין שלב 🟢 בשיעור הזה: את המשחק בונים בעצמם.
  • תפקידים: חמישה כרטיסים (עמודים 2–3). סטודיו של 4: הבודק/ת הוא גם המפעיל/ה. סטודיו של 3: המנהל/ת גם מפעיל/ה, והמתכנת/ת גם בודק/ת. סטודיו של 6: שני מתכנתים (נהג/ת ונווט/ת) שמתחלפים כל 7 דקות.
  • הניקוד: הכול בנקודות, בתוך השיעור בלבד. לוח הניקוד במצגת מתעדכן בלחיצה (+/−, ✓), וגם דף הניקוד המודפס (עמוד 15) כגיבוי.

שליף MakeCode Arcade למדריך

MakeCode Arcade (arcade.makecode.com) הוא סביבה חינמית של Microsoft לבניית משחקי רטרו בבלוקים, בדפדפן, בלי הרשמה. המסך 160×120 פיקסלים, 16 צבעים. משמאל סימולטור (חצים = ג׳ויסטיק, רווח = A). אפשר לעבור ל-JavaScript או Python בלשונית למעלה, אבל בשיעור נשארים בבלוקים. שפת הממשק: גלגל השיניים ← Language (שמות הבלוקים כאן באנגלית, כמו בברירת המחדל).

המכונה הבסיסית, צעד אחר צעד (זה מה שמדגימים בשקף 10)

  1. New Project ← שם. בסביבת העבודה כבר יש בלוק on start.
  2. Sprites ← set mySprite to sprite [ ] of kind Player לתוך on start. לחיצה על הריבוע האפור פותחת את עורך הפיקסלים (16×16 כברירת מחדל): עיפרון, דלי, מחק, ולמעלה לשונית Gallery עם דמויות מוכנות.
  3. Controller ← move mySprite with buttons. Sprites ← set mySprite stay in screen ON.
  4. Info ← set life to 3.
  5. Game ← on game update every 500 ms ← משנים ל-2000. בתוכו: Sprites ← set projectile to projectile [ ] from side with vx 50 vy 50 ← משנים ל-vx -60, vy 0 (נכנס מימין). מתחתיו set projectile y to + Math ← pick random 10 to 110. ואז set projectile kind to Enemy.
  6. Sprites ← on sprite of kind Player overlaps otherSprite of kind Enemy. בתוכו: Info ← change life by -1, ו-Sprites ← destroy otherSprite (אפשר להוסיף effect).
  7. ניקוד: אירוע נוסף שיוצר פריט מסוג Food, ועוד אירוע התנגשות Player ↔ Food עם change score by 1 ו-destroy otherSprite.
  8. סוף: Info ← start countdown 30 (s) ב-on start, ו-on countdown end ← Game ← game over WIN. כשהחיים מגיעים ל-0, MakeCode מסיים בהפסד לבד.
  9. שיתוף: Share (למעלה) ← שם ← Share Project ← Copy. כל שיתוף הוא "צילום" של הגרסה באותו רגע. אחרי שינוי משתפים שוב.
  10. גיבוי: Download שומר את הפרויקט כקובץ PNG ("מחסנית"), שאפשר לגרור חזרה לדף הבית של MakeCode כדי לפתוח שוב.

"הולך וקשה": תוספות שכיחות

  • מהירות שעולה: במקום vx -60, בלוק Math: -60 - score (Info ← score).
  • עוד אויבים: אירוע on game update שני עם מרווח אחר.
  • אויב שרודף: set myEnemy follow mySprite (Sprites).
  • שלב שני: if score ≥ 10 (Logic) ← Scene ← set background image.
  • אנימציה: Animation ← animate mySprite frames [ ] interval 500 ms loop ON.
  • מסך פתיחה: Game ← splash "שם המשחק" בתחילת on start.
  • צליל: Music ← play sound בתוך אירוע ההתנגשות.

גרסה מלאה בלי מכשירים: "ארקייד על נייר"

אותו סיפור, אותם תפקידים, אותו ניקוד ואותו מרתון. מה שמשתנה: המכונה היא דף A3, ו"המחשב" הוא המפעיל/ה.

  1. ספרייטים (ספרינט 1, 10 דק׳): אמן/ית הפיקסלים מצייר/ת 2 ספרייטים על דפי הרשת 16×16 בטושים (רק בצבעים של הפלטה), גוזר/ת ומדביק/ה על פקקים או קוביות קטנות.
  2. המסך (A3): רשת של 10×8 משבצות. מסמנים התחלה, אזור שממנו "נכנסים" אויבים, ומונה ניקוד וחיים בצד.
  3. הקוד (ספרינט 1, 10 דק׳): המתכנת/ת כותב/ת 4–6 חוקים בשפת "כאשר... אז..." על דף חוקי המכונה (עמוד 16), למשל: "כאשר מתחילים, אז לשחקן 3 חיים" · "כאשר השחקן מטיל קובייה, אז הוא זז כמספר המשבצות" · "כאשר עובר תור, אז אויב חדש נכנס בשורה של הקובייה" · "כאשר השחקן נוגע באויב, אז חיים פחות 1, והאויב יוצא מהלוח".
  4. בדיקת מכונה: שחקן מסטודיו שכן משחק, והמפעיל/ה מבצע/ת את החוקים בדיוק כפי שנכתבו. כשהמפעיל/ה לא יודע/ת מה לעשות, זה באג. הבודק/ת רושם/ת אותו.
  5. ספרינט 2: מתקנים חוקים, מוסיפים "הולך וקשה" (למשל: "כאשר הניקוד 5, אז נכנסים 2 אויבים בכל תור"), וכותבים כרטיס מכונה.
  6. מרתון: זהה לגרסה הממוחשבת: כרטיסי שחקן, פיקסל זהב, דף שיאים לכל מכונה, החלפת מפעילים באמצע.
  7. הגשה: צילום של הלוח, הספרייטים ודף החוקים, או איסוף הדפים למעטפה.
זה גם שיעור מצוין על "מה זה קוד": המחשב לא מנחש. מבצע רק את מה שכתוב.
